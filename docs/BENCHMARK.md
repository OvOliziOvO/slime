# GPU benchmark methodology

## 指标

```text
throughput = (2 * radius + 1)^2 / wall_time
```

结果以十亿候选中心/秒（B/s）显示。Wall time 包含 Kernel 同步、候选复制和主机排序，因此更接近 GUI 的实际体验。

## 推荐流程

1. 关闭占用 GPU 的其他程序。
2. 插电并固定同一种性能/散热模式。
3. 先运行一次短扫描完成 CUDA 初始化。
4. 比较实现时采用 `A, B, B, A` 交错顺序，至少各运行五次。
5. 使用中位数作为主要结果，同时记录最好值。
6. 对拍候选总数以及完整 `(score, x, z)` 集合。
7. 通过 `build_gpu_x64.bat` 的 ptxas 输出记录 registers 和 spill。

仓库提供了可重复的对拍/交错测试脚本：

```powershell
python .\tools\benchmark_gpu.py --radius 80000 --threshold 45 --cycles 3
```

## 当前参考结果

硬件：RTX 3060 Laptop GPU（sm_86），半径 80,000。

| 阈值 | V34 热态中位数 |
|---:|---:|
| 45 | 约 91.7 B/s |
| 50 | 约 105.5 B/s |

不同测试轮次受温度影响明显，表格只用于本机回归，不代表其他 GPU 的保证性能。

V34 不再将全图位图写回显存。每个 Block 在共享内存维护 32 行压缩位图环，
每个中心只滚动方形分数；通过安全方形上界的候选只统计圆外 68 个角落格，
以 `circle = square - corners` 得到精确圆形分数。大范围搜索会在 128×8、256×4、256×8、512×4
之间短测并缓存当前设备的胜者，可用 `SLIME_GPU_V34_SHAPE` 强制覆盖。

正式构建还同时编译原生 48 位 LCG、等价的 32 位分片 LCG 和截断首输出
LCG。达到 1000 亿中心时，V34 会用交错顺序短测三条路径并校验命中数；只有替代版至少快 3%
才会采用它，结果按设备和阈值区间缓存在当前进程。可用
`SLIME_GPU_V34_RNG=native`、`limb32` 或 `truncated` 强制覆盖。RTX 3060 Laptop 的交错
平均测试中，截断版慢约 15%～18%，因此自动选择 Native；
Pascal 等架构由运行机器自己的短测决定，不套用 3060 的结论。

最小规模低于 42 时仍使用 V34。密集模式将精确命中数保存在每线程局部计数器中，Block 结束时归并；候选结果使用可回退的高分物化门槛，避免把数亿低分命中写回主机。种子 1、半径 500,000、阈值 40 的角落差分版本为 12.413 秒，改动前为 21.891 秒；两者总命中均为 175,811,264，Top‑1,000,000 SHA-256 均为 `95a2776bcef5a04639ada1489076fb37b7e238543c3e12c3727b0e743f83d4af`。

大范围搜索采用分 Slab 全局 Top-K：每个 Slab 的候选复制到主机后按分数桶
增量裁剪，只在临界分数桶比较坐标。若单个 Slab 超过设备候选容量，会减半
Slab 高度并重试，因此发现总数超过缓冲上限时仍能得到严格的全图 Top-K。

RTX 3060 Laptop、种子 123456789、阈值 45、半径 500,000 的 V34 实测为
3,590,289 个命中。保留全局 Top 1,000,000 用时约 11.53 秒，吞吐约
86.7 B center/s。总命中数与完整输出缓冲 SHA-256 已固定为回归基准。
功耗和温度会造成明显波动。

## CPU 基准

CPU 指标使用相同的候选中心口径，以 `Mcenter/s` 显示。推荐保留优化前
DLL，并用同一进程参数分别测试：

```powershell
python .\tools\benchmark_cpu.py --dll .\slimecore.dll `
  --reference-dll .\slimecore_cpu_baseline.dll `
  --radius 20000 --threshold 45 --threads 20 --cycles 5
```

参考机器为 i7-12700H（14 核、20 线程）。半径 20,000、阈值 45 时，旧标量
核心热态约 1.3 B center/s，AVX2 八路核心约 3.4–3.6 B center/s。阈值 25
会返回数亿个匹配项，此时精确复核和结果排名占主导，哈希向量化收益会明显缩小。
